# 面试讲解手册：知库问答（知识库问答产品）

## 一句话介绍

"这是我做的一个团队知识库问答产品：多知识库隔离、文档版本管理、混合检索问答只是基础，重点是反馈闭环——用户点'无用'的回答进待优化看板，顺着它补文档，回答质量越用越好，数据看板能量化看到无答案率和好评率的变化。"

## 面试官深挖 Q&A

**Q：多知识库隔离是怎么实现的？**
A：三层。业务层：kb_base 表，文档/会话都带 kbId；向量层：每个向量 metadata 里有 scope="{kbId}:current"，检索时 `filterExpression(eq("scope", ...))` 精确过滤；关键词层：SQL JOIN 版本表同时过滤 `v.is_current=true AND d.kb_id=:kbId`。三层语义一致，不会出现向量查到 A 库、关键词查到 B 库的分裂。

**Q：版本回滚为什么不需要重新向量化？**
A：因为检索从来不删旧版本的向量，只是用 scope 区分。回滚=两步：DB 里翻转版本的 isCurrent；一条 SQL 把该文档向量的 scope 先全置 archived，再把目标版本的置 current（`jsonb_set(metadata,'{scope}',...)`，Spring AI 没提供改 metadata 的接口，直接操作 pgvector 的 JSONB 列）。整个过程毫秒级。

**Q：scope 字段为什么不用两个条件拼 AND？**
A：Spring AI 不同版本的 FilterExpressionBuilder 对复合条件的 API 有差异，容易踩坑。用一个 scope 字符串把"知识库+是否当前"编码在一起，检索侧永远是一个 eq，简单且稳定。这是刻意的设计取舍。

**Q：怎么证明你的 RAG 是 work 的？**
A：三层证据。第一，`eval/golden.jsonl` 测试集分 normal 和 adversarial 两类，`eval/eval.py` 一键跑出 Recall@5、拒答正确率、首字延迟，结果写进 `last_result.json`，数据看板直接展示；第二，线上无答案率（拒答数/回答数）是真实用户行为指标；第三，反馈好评率。调参（阈值、chunk 大小、topK）每次都跑回归，凭数据不凭感觉。

**Q：chunk 大小 800 字、阈值 0.70 怎么定的？**
A：经验值 + 可调。chunk 太大 embedding 语义被稀释、召回精度下降；太小则上下文碎。bge-m3 的余弦相似度下，相关 chunk 一般在 0.72~0.9，无关的在 0.5~0.65，0.70 是分界线。所有参数收敛在 application.yml 的 `rag:` 配置段。

**Q：为什么用 pgvector 而不用 Milvus？**
A：这个体量下 pgvector 足够（百万级向量 HNSW 毫秒级）；业务数据（文档/会话/反馈）和向量在同一个 Postgres 里，少一个组件；向量 metadata 的 JSONB 可直接 SQL 操作（版本回滚就靠这个）。数据量到千万级再迁，Spring AI 的 VectorStore 是接口，迁移成本低。

**Q：@Async 异步向量化有什么坑？**
A：两个。第一，@Async 靠 Spring 代理实现，必须放在独立 Bean 里（DocumentIndexService），同类自调用会绕过代理、异步静默变同步；第二，upload() 是 @Transactional 的，外层事务提交前异步线程可能读不到版本行，我加了带上限的重试而不是直接放弃，避免文档卡在 PROCESSING。

**Q：无答案率这个指标怎么算的？**
A：ChatMessage 上有个 refused 字段，检索无命中走固定拒答话术时记 true。看板统计 refused/assistant 消息总数。这比"在代码里字符串匹配"可靠，是落库时的事实记录。

**Q：待优化看板对产品有什么用？**
A：它是知识库运营的抓手。无用回答集中展示问题、回答摘要、用户备注、引用了哪些文档——运营者一眼看出"哪类问题答不好、缺哪份文档"，补完文档标记 fixed。没有这个闭环，知识库就是一次性 demo，越用越准才是产品。

**Q：删除文档/知识库时怎么保证不留脏数据？**
A：三处同步清：向量库按 documentId 删全部版本向量、关系表 chunk 按 documentId 删、版本行 + 落盘原文件删除。知识库删除时级联调文档删除，再清该库会话。不清的话，被删文档的 chunk 会继续被召回，这是 RAG 系统典型的数据一致性坑。

## 演示话术（给面试官现场跑，3 分钟）

1. 建库传文档（30s）："这是知识库列表，建一个'考勤制度'库，上传 pdf，后台异步向量化，前端轮询进度。"
2. 改文档传 v2（30s）："改几个字重新上传同名文件——注意这里生成了 v2，检索永远只查当前版本。"
3. 问答+引用（60s）："选这个库提问，看流式回答和引用卡片，点卡片直接跳到文档详情。"
4. 反馈闭环（30s）："点无用、写备注，待优化看板实时出现，处理完标记 fixed。"
5. 回滚+看板（30s）："把 v1 设为当前，检索立即切回；数据看板看无答案率和评估结果。"

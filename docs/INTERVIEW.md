# 面试讲解手册：智能知识库问答系统（RAG）

## 一句话介绍

"这是我做的一个企业级 RAG 知识库问答系统：用户上传文档后自动向量化入库，提问时走检索增强生成，流式返回带引用来源的答案；核心工作在切分策略、检索召回质量和防幻觉三块。"

## 简历描述（可直接用）

> **智能知识库问答系统**｜Spring Boot 3 + Spring AI + pgvector + Vue3
> - 设计两级文本切分策略（标题语义粗切 + 滑动窗口细切），解决答案落在切分边界导致的检索丢失
> - 实现"向量召回 → 相似度阈值过滤 → 去重"的检索链路，无命中直接拒答，配合 Prompt 约束将幻觉率降到最低
> - 文档向量化走 @Async 异步管线，上传接口秒回、前端轮询进度；SSE 流式推送问答结果，首字延迟 < 2s

## 面试官深挖 Q&A

**Q：为什么选 pgvector 而不是 Milvus / Qdrant？**
A：三个原因。一是 demo 体量下 pgvector 足够（百万级向量 HNSW 检索毫秒级）；二是业务数据（文档/会话/消息）和向量在同一个 Postgres 里，少一个组件、事务一致性好做；三是运维简单，一个 docker 镜像搞定。数据量到千万级再迁 Milvus，Spring AI 的 VectorStore 是接口，迁移成本低。

**Q：为什么要做混合检索？RRF 是什么？**
A：纯向量检索有个经典翻车：用户问"去年 Q3 财报"，向量会召回"今年 Q3 财报"——语义高度相似，但时间错了。关键词检索（这里用 pg_trgm 三字符相似度，对中文按字切分有效）擅长"去年/Q3"这类字面约束。两路结果用 RRF 公式 `score = Σ 1/(60+rank)` 融合，正确 chunk 在两路排名都靠前的话分数显著拉开。实现在 `RetrievalService`，融合后引用来源会标注"向量/关键词/向量+关键词"，前端直接展示。

**Q：怎么证明你的 RAG 是 work 的？（评估）**
A：我建了 golden 测试集（`eval/golden.jsonl`），分 normal（答案在文档里）和 adversarial（文档里没有、期望拒答）两类，覆盖时间限定词、数字精确匹配、跨 chunk 推理、对抗幻觉四种翻车点。`eval/eval.py` 一键跑出 Recall@5、拒答正确率、首字延迟。每次调参（阈值、chunk 大小、topK）都跑一遍回归，记录在 `docs/EVAL.md` 的变更日志里——优化凭数据不凭感觉。

**Q：chunk 大小 800 字、阈值 0.70 怎么定的？**
A：经验值 + 可调。chunk 太大 embedding 语义被稀释、召回精度下降；太小则上下文碎。阈值 0.70 是在测试集上试出来的：bge-m3 的余弦相似度，相关 chunk 一般在 0.72~0.9，无关的在 0.5~0.65。所有参数都收敛在 application.yml 的 `rag:` 配置段，方便按业务调。

**Q：怎么评估 RAG 效果？**
A：目前是人工抽查 + 看引用来源是否对得上。生产级做法：构造"问题-标准答案-相关文档"三元组测试集，算召回率（答案 chunk 是否在 topK 里）和答案忠实度（用 LLM-as-judge 打分）。这是后续要补的。

**Q：SSE 和 WebSocket 怎么选？**
A：问答是纯服务端向客户端单向推送，SSE 更轻：自动重连、就是 HTTP、不需要维护长连接状态。WebSocket 留给双向场景（如协同编辑）。

**Q：大模型挂了 / 超时怎么办？**
A：`SseEmitter.completeWithError` 兜底，前端显示错误；检索链路本身不依赖大模型（无命中直接拒答不调模型，省钱）。生产上再加熔断和降级话术。

**Q：多租户 / 权限控制怎么做？**
A：当前是单用户 demo。生产方案：向量 metadata 里加 `tenantId` / `docAcl`，检索时用 FilterExpression 拼权限过滤，保证 A 租户永远搜不到 B 租户的 chunk。

## 演示话术（给面试官现场跑）

1. 打开「文档管理」，上传一份课程 PDF → 展示"解析中"状态 3 秒后变"已入库（N 块）"。
2. 切到「问答对话」，问一个文档里的问题 → 展示打字机流式输出 + 展开"引用来源" → 指着相似度说"这是向量召回的分数"。
3. 问一个文档里没有的问题 → 展示拒答话术 → "这就是防幻觉，宁可不答也不编"。
4. 最后翻 application.yml 的 `rag:` 配置段 → "所有 RAG 参数可调，这是我调优的抓手"。

# RAG 评估体系（Evaluation）

面试官区分"调包侠"和"做过项目"的核心证据：**你有没有量化地证明你的 RAG 是work的**。
本目录提供一套轻量、可运行的黑盒评估方案。

## 1. 构造 Golden Set

`eval/golden.jsonl`，每行一条：

```json
{"question": "2024 年 Q3 财报的净利润是多少？", "expected_files": ["2024年财报.pdf"], "type": "normal"}
{"question": "公司去年的团建去了哪里？", "expected_files": [], "type": "adversarial"}
```

- `type=normal`：答案在文档里，期望系统能答对（引用来源包含 expected_files）。
- `type=adversarial`：答案不在文档里（或问题本身有陷阱），期望系统**拒答**而不是编造。
- 先从 30~50 条起步，面试时说"当前 50 条，目标 200 条"——诚实比数字大更重要。

出题技巧（覆盖 RAG 的典型翻车点）：
1. 时间限定词："去年 Q3" vs "今年 Q3"（考混合检索）
2. 数字/型号精确匹配："A100 显卡的显存是多少"（考关键词检索）
3. 跨 chunk 推理：答案分散在两个 chunk 里（考切分 overlap）
4. 对抗：文档里没有的信息（考拒答/防幻觉）

## 2. 运行评估

```bash
# 确保后端已启动（http://localhost:8080），且文档已入库
cd eval
python3 eval.py --base http://localhost:8080 --golden golden.jsonl
```

输出示例：

```
共 50 题
召回率 Recall@5（答案来源命中 expected_files）：86.0%
拒答正确率（对抗题正确拒答）：92.3%
平均首字延迟：1.4s
```

## 3. 指标定义（面试话术）

- **Recall@5**：标准答案所在文档出现在引用来源里的比例。调优切分/阈值/融合权重就看它涨没涨。
- **拒答正确率**：对抗题里系统说"无法回答"的比例。阈值设太低会幻觉、设太高会误拒答，两者要一起看。
- **引用覆盖率**（人工抽查）：答案里的每个事实句都能在引用来源中找到原文。

## 4. 迭代方法论（讲给面试官听）

> "我每调一次参数（比如阈值 0.70→0.65，或 chunk 从 800 改 1200），就跑一遍评估集看 Recall@5 和拒答率的变化，保证优化不是凭感觉。比如有一次把 topK 从 5 放到 8，召回涨了 4 个点但首字延迟多了 0.6s，最后折中选了 8+流式——这些取舍我都记在 EVAL.md 的变更日志里。"
